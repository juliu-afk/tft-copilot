## 2. 核心数据结构（snapshot.py）

```
@dataclass(frozen=True)
class UnitOnBoard:        # 感知 UnitBox 的决策层投影（解耦：不依赖感知类型）
    unit_id: str
    cost: int
    star: int | None      # None -> 一星基线（E4）
    score: float          # 感知置信度，<0.45 的 pending 剔除（A2）

@dataclass
class BoardSnapshot:      # 自家回合快照（感知 -> 决策单入口）
    round_no: int
    scene: str
    quality: float        # 感知质量 0-1，<0.3 四模块 Silent（E1）
    my_units: list[UnitOnBoard]
    layers: int | None
    hp: int | None
    gold: int | None
    level: int | None

@dataclass
class PlayerState:        # 全场一家（含自己）
    player: str           # 'me' | 'p1'..'p7'
    units: list[UnitOnBoard] | None   # None = 未侦查（E6/诚实原则）
    hp: int | None
    hp_history: list[int] # 近5回合血量序列（趋势分量）

@dataclass(frozen=True)
class Advice:
    level: str            # info | warn | critical | silent
    text: str
    source: str           # layer_progress | power_score | matchup | impact
```

E2 层数卫兵：LayersGuard.track(new) -> int | None。规则：只接受比上次大 0-100 的变化；首帧任何值都接受；违规返回 None 丢弃。

## 3. 模块(1) 层数进度（layer_progress.py）

MILESTONES = [10, 25, 50, 100, 200, 300, 400, 500, 625, 1000, 1250]（工程方案 5.1 原表）。

规则（每条带 once 去重，fired 集合按 match 生命周期）：
- R-milestone-pre：layers == N-1 -> info「下一档奖励：{options}，还差 1 层」
- R-milestone-hit：layers == N -> info「达成 {N} 层档：{options}」
- R-stop：layers >= 500 and hp < 40 -> critical「500 分水岭+岩宝达标即停，别贪」
- 奖励内容来自 rules.rewards（layers 匹配）；不在 rewards 的里程碑只提示层数

## 4. 模块(2) 战力评分（power_score.py）

```
战力分(0-100) = 0.35*star + 0.25*trait + 0.25*item + 0.15*trend   # D5 初始权重
star  = sum(unit_power) / board_max * 100
        unit_power = (row.hp + 10*row.ad) / 1000，row 取 stars[min(star or 1, 3)-1]
        board_max = 10 * max(all units star3 row_power)   # 从数值库加载期计算，无魔法常数
trait = min(sum(min(count, 6) for active traits) * 1.5, 100)  # D1 激活数近似，M4 换断点表
item  = 0    # 装备识别 M5
trend = clamp(50 + mean_slope * 5, 0, 100)，slope = 近5回合血量平均每回合变化（掉血快分低）
```

输入 PlayerState.units 为 None -> 整体返回 None（诚实原则）；units 空 -> 各分量按 0 计。
score < 0.45 的 UnitOnBoard 在入口统一剔除（A2，与感知 pending 阈值一致）。

## 5. 模块(3) 对位预测 L0（matchup.py）

```
diff = my_power - opp_power            # 双方 None -> 返回 unknown 档（E6）
winrate = 1 / (1 + exp(-0.08 * diff))  # sigmoid：diff 0->50%，+20->82%，-20->18%
tier:   winrate >= 0.65 高 / 0.35-0.65 五五开 / < 0.35 低
confidence: high  = 双方数据齐 且 |diff| >= 15
            low   = 任一方数据缺 或 |diff| < 8
            mid   = 其余
```

输出 MatchupPrediction(winrate, tier, confidence)，落库带 confidence 供四象限统计（A3）。
k=0.08 为初始标定：典型分差 +-25 覆盖 12%-88% 区间；M6 回归重估。

## 6. 模块(4) 影响推演（impact.py）

输入：MatchupPrediction + 任务状态 TaskState(streak_type: win|lose|none, streak_count) + 快照。

| 规则 | 触发 | Advice |
|---|---|---|
| R-streak-break | streak=win 进行中 且 tier=低 | warn「连胜第{N}场，预测胜率 {p}%，断连风险高」 |
| R-intentional-lose | streak=lose 进行中 且 tier=高 | critical「连败第{N}场，预测会赢——需主动控血保连败」 |
| R-lose-streak-win | streak=lose 且 tier=低 | info「预测输，连败保住+掉层养血，正合连败流」 |
| R-fragments | 下一奖励档距 layers <= 5 | info「距 {N} 层档（{options}）还差 {d} 层」 |
| 降级 | TaskState=None（E5） | 只出 R-fragments，不提任务 |

与模块(1)文案去重：engine 按 (source, text 前缀) 合并。

## 7. 对局库（store/db.py）

```sql
CREATE TABLE IF NOT EXISTS matches (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    start_time TEXT NOT NULL, end_time TEXT,
    version TEXT NOT NULL,          -- 版本化铁律：与知识库 patch 一致才允许写
    final_layers INTEGER, final_place INTEGER, win_loss TEXT
);
CREATE TABLE IF NOT EXISTS rounds (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    match_id INTEGER NOT NULL REFERENCES matches(id),
    round_no INTEGER NOT NULL, version TEXT NOT NULL,
    scene TEXT, quality REAL, layers INTEGER, hp INTEGER, gold INTEGER, level INTEGER,
    my_units TEXT,             -- JSON [{unit_id,cost,star,score}]
    power_score REAL,          -- 自家战力分
    opp_player TEXT, predicted_winrate REAL, prediction_confidence TEXT,
    actual_result TEXT,        -- W / L / I(故意输) / NULL
    advices TEXT               -- JSON [{level,text,source}]，replay 展示用（对工程方案9.1的加列扩展）
);
```

- 库文件 data/db/matches_v18.6.db（D6 版本化文件名）；WAL 模式；PRAGMA foreign_keys=ON
- 版本不匹配 -> MatchStoreVersionError 拒写（铁律：版本不匹配的数据拒绝入库）
- E7 文件锁：OperationalError -> 决策层降级内存模式（store=None 路径），Toast 提示一次
- 断线续采（US-6b）：open_unclosed() -> list[match_id]；resume 走既有 match_id 继续写 rounds

## 8. HUD（overlay/hud.py）

```
class HUDBase(ABC):
    update(state: HUDState) -> None    # 顶栏层数+里程碑距离 / 8家战力条 / 底栏提示
    toast(advice: Advice) -> None      # info蓝 warn黄 critical红，Console 用 ANSI，Overlay 用 QColor
    toggle() -> None                   # F9 钩子（Overlay keyPressEvent；Console 无操作占位）
    close() -> None

def create_hud(prefer: str = 'auto') -> HUDBase   # auto: PyQt6 可用->Overlay 否则 Console（D4/A7）
```

HUDState: layers/next_milestone_dist/players(list[(name, score|None)])/latest advices。
OverlayHUD：Qt.FramelessWindowHint | WindowStaysOnTopHint | Tool，半透明黑底白字，
右下角 260x360，战力条用 QLabel 富文本（█ 重复），不抢焦点（Qt.WindowDoesNotAcceptFocus）。
CI 无 GUI 无 PyQt6 -> create_hud() 返回 ConsoleHUD，测试全走 Console 路径。

## 9. 编排（engine.py）

```
class DecisionEngine:
    def __init__(rules, units_book, store=None, hud=None)   # store/hud 可缺省（纯函数模式，测试友好）
    def start_match(version) -> int                        # 建 match 行，返回 match_id
    def on_round(snap: BoardSnapshot, players: dict[str, PlayerState] | None,
                next_opp: str | None, task: TaskState | None) -> list[Advice]
        # 质量门卫 -> 层数卫兵 -> 四模块 -> 去重 -> HUD -> 落库
    def record_result(round_no, result: 'W'|'L'|'I')       # 补 actual_result（复盘四象限燃料）
    def close_match(final_place, final_layers, win_loss)   # 闭合 matches 行
```

单轮预算 50ms：全部纯 Python dict/list 运算，无 IO 循环（A8 性能测试断言）。

## 10. CLI（decision_check.py + replay_cli.py）

```
tft-copilot decision-test [--db PATH] [--rounds N]   # 合成局冒烟：8家x30回合端到端（A9）
tft-copilot replay --match N [--round R] [--db PATH]
tft-copilot stats --quadrant [--db PATH] [--match N]
tft-copilot export --csv DIR [--db PATH]
```

- decision-test：seeded RNG 造合成局（随机阵容从数值库抽卡、层数递增、血量递减），跑 engine 全链路，
  落库后自动调 replay 输出最后 5 回合摘要 + 四象限一行，退出码 0 = 冒烟通过
- export 用标准库 csv（零新依赖；polars 留给用户侧 PowerBI 链路）
- stats 样本 <20 输出「样本不足，仅供观察」警示（PRD 7.1）
