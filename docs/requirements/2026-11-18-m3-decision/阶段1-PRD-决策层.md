# 阶段1-PRD-M3 决策层（规则引擎 + 对局库 + HUD + 复盘回放）

> 批次：2026-11-18-m3-decision | 状态：基线（用户已授权连续执行）
> 上游：工程方案 v1.1 第 5/8/9 章 + M2 感知层（UnitBox/数字/场景）+ M1 知识库（rules/units JSON）

## 1. 背景与用户问题

M2 装上了眼睛，M3 要装上大脑：把感知输出变成可执行的决策建议。

用户核心痛点（按工程方案 5.1-5.4）：

1. **层数里程碑错过**：20 档奖励与 38 任务的层数节奏埋在攻略里，局中靠脑记，常错过关键节点（500 分水岭/625 档/1000 档）
2. **全场信息盲区**：自己阵容质量心里有数，对手 7 家强度全靠猜，追三/卖血时机拍脑袋
3. **对位预测缺失**：下回合打谁、胜率多少、该激进还是卖血，无量化参考
4. **胜负影响看不清**：赢/输对任务/层数/血量/名次四条线的交叉影响，局中算不过来（典型：连败流故意输 vs 碎片到手）
5. **数据不沉淀**：打完一局什么都没留下，战力评分权重无法自校准，复盘无从谈起

前提约束（继承）：三红线（零输入模拟/零进程读取/零联网外传）；决策纯规则引擎零 LLM；性能预算感知 150ms/帧 + 决策 <=50ms/次。

## 7. 对抗性验证（复杂需求四阶段必做）

### 7.1 自问自答

**Q：决策层与感知层的解耦边界在哪？**

A：感知层输出 UnitBox/数字/场景 -> 汇总为 BoardSnapshot（回合快照）-> 决策层消费快照。决策层不 import 感知层任何符号（模块级隔离，semgrep 可查）。

**Q：识别失败时决策层会不会拿脏数据出错误建议？**

A：决策层入口做门卫：BoardSnapshot 带感知质量分 quality（0-1，识别成功率加权），quality < 0.3 时四模块输出 Silent（不输出建议，只保活状态），防止误导。

**Q：战力评分的输入如果只有部分家（Tab 巡视没看全 8 家）？**

A：缺失家记 Unknown，评分输出 None（HUD 条形图显示灰色），不猜测补齐——诚实原则。

**Q：HUD 在双显示器/不同分辨率下会不会遮挡？**

A：M3 只保证 1920x1080 锚点坐标系正确（M2 已建 1920x1080 合成基准）；多分辨率适配 M6 校准一并处理。

**Q：四象限统计样本不足时 stats --quadrant 会误导吗？**

A：样本 <20 时输出警示行「样本不足，仅供观察」——防误导。

- 零输入模拟：决策层不模拟任何输入。HUD 快捷键为只读钩子（F9 开关 HUD 自身，不触碰游戏）
