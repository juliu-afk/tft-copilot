## 3. 红线专项复核（本次审查最重要发现）

### 3.1 M2 假阴性问题

本次审查发现 M2 时期 semgrep 门禁实际失效：

- 三条红线规则的 from X import ... 模式在 semgrep 1.164 下 PatternParseError（规则加载失败）
- no-secrets 的 metavariable-regex 位置错误（顶层非 patterns 内），未生效，产生 22 处误报同时掩盖真问题

即 M2 报告的「semgrep 0 findings」是规则失效导致的假阴性，非代码真干净。

### 3.2 修复与验证闭环

1. 语法修复：pattern-either + from X import $X；metavariable-regex 移入 patterns + ^...$ 锚点
2. 负向验证：全库扫描 0 findings（真 0，规则已加载）
3. 正向验证：恶意样本（pyautogui/requests/socket/API_KEY/win32api）9 findings，4 类规则全部命中

结论：红线防线已从假阴性恢复为真实有效。CI（ci.yml）使用同一规则文件，同步受益。

### 3.3 流程改进建议（并入 CLAUDE.md 下次修订）

semgrep 门禁必须包含正向验证步骤：每次改规则文件后跑恶意样本确认规则活着。0 findings 只有在正向验证通过后才有意义。
