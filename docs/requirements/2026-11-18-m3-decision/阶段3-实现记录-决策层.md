## 3. 实现期修正（含方案微调）

### 3.1 战力评分基准（star==3 均值，微调自方案的均值基准）

方案写「全库星级行(star>=3)平均能量」，实现时发现 star>=3 混档（4/5/6 星极端行拉高均值）导致梯度压缩（一星 17 vs 三星 21，无区分度）。实测改为 star==3 行均值 x10 为 100 分锚点：一星阵容约 27 分、三星成型 33 分、六星顶配 44 分（同名阵容羁绊分低），梯度恢复。修正理由：基准语义从「均值」明确为「三星成型线」，与直觉一致且可解释。

### 3.2 对位预测上下界（方案外增强）

sigmoid k=0.08 在分差 50 时输出 98.2%，文案「预测胜率 2%」过于武断且污染四象限统计。加 0.05-0.95 上下界压缩（WR_FLOOR/WR_CAP 常量），语义「L0 引擎不给绝对值」。

### 3.3 semgrep 规则修复（重要：M2 遗留假阴性修复）

实现期跑门禁发现 M2 遗留问题：

- 三条红线规则（input/process/network）的 `from X import ...` 模式在本机 semgrep 1.164 下 PatternParseError —— **规则加载失败，红线扫描实际失效**
- no-secrets 规则的 metavariable-regex 写在规则顶层，未生效，退化成「匹配所有字符串赋值」产生 22 处误报（tier="high" 也报密钥）

修复：`from X import ...` 改为 pattern-either + `from X import $X`；metavariable-regex 移入 patterns 内并加 ^...$ 锚点。修复后：全库 0 findings + 恶意样本正向验证 9 findings（4 类规则全命中）——**红线防线从假阴性恢复为真实有效**。

教训（写入 M2/M3 交接）：**semgrep 门禁必须做正向验证（恶意样本测试），0 findings 可能是规则失效而非代码干净**。CI 同步受益。
