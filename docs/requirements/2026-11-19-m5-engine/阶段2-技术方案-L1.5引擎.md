## 3. 模块设计

### 3.1 装备数值库 schema（data/equips/equips_18.6.json）

```json
{
  "schema_version": 2,
  "meta": {"patch": "18.6", "version_id": "16_18.18.1_S400001", "count": 204, "source": "jinchanchan.fun equip API"},
  "equips": [
    {
      "id": 2001, "name": "无尽之刃", "type": "成型装备",
      "grade": 1.0, "synth": [1001, 1009],
      "desc": "获得【技能暴击】……"
    }
  ]
}
```

- grade 权重表（模块级常量 GRADE_BY_TYPE，power_score.py）：
  - 成型装备 1.0 / 光明武器 1.6 / 神器装备 2.5 / 转职纹章 0.8 / 特殊装备 0.3 / 基础装备 0.25
  - WHY：以「同等价值成装=1.0」锚定。光明≈成装×1.6（掌盟常规溢价），神器独立掉落强度最高；纹章不加数值只扩羁绊入口按 0.8 计；特殊装备多为组件/消耗品；基础散件弱。数值为设计初值，M6 回归重估（与 W_STAR 等权重同批）。
- id 排序连续性校验沿用 cards 校验思路：id 升序 + 类型分布快照。

### 3.2 equips_loader.py（knowledge 层）

- EquipsBook dataclass：equips tuple + _index {id: Equip} + by_id()。
- 三重校验：文件名 patch == meta.patch == meta.count == len(equips)；type 必须在六类枚举内；id 唯一。
- 加载失败抛 EquipsDataError（对齐 units/traits/cards 风格）。

### 3.3 PanelEngine（decision/panel.py）

**职责**：PlayerState → 结算面板三轴分（0-100）。

```
PanelScores = dataclass(dps, ehp, burst)  # 三轴均 0-100 归一

assemble(state):
  units 为 None → return None（E6 诚实）
  trusted = 过滤 score>=0.45
  逐子：
    row = units_book.get(id).stars[star]
    base_power = (hp + 10*ad)/1000            # 沿用 power_score 单子能量
    dps_i = base_power * 攻速系数 + 装备 dps 增益(grade*0.1)
    ehp_i = base_power * (1 + 装备 ehp 增益(grade*0.06))
    burst_i = base_power * (mana_max - mana_start < 40 ? 1.2 : 1.0)  # 低蓝条=高爆发
  羁绊乘区（真实断点替代激活数近似）：
    for trait, active in Counter(units.traits):
      w = traits_book.get(trait).breakpoint_weight(active)   # M4 已实现 k/len
      dps_total *= (1 + 0.08*w); ehp_total *= (1 + 0.06*w)   # 断点乘区系数
  归一：除以满配基准（全库 star3 平均能量×10，同 power_score 口径）
  站位修正（可选 pos_ctx）：见 §3.5
```

- 性能预算注释：`# budget: <5ms/次`（122 弈子×10 格查表 + Counter 归并）。
- 与 PowerScorer 的关系：**并存不替代**。power_score 输出 HUD 战力条形图（单分数，直观），panel 输出对位引擎三轴（细粒度）。M6 校准后可评估合并。

### 3.4 predict_l15（decision/matchup15.py）

```
L15Prediction(engine, winrate, tier, confidence, detail)
  engine: "L1.5" | "L0"

predict_l15(my_panel, opp_panel, pos_ctx=None):
  任一 None → fallback predict(L0 power 分差)：从 panel 反推不了 power，
             由调用方（engine.py）传 L0 分数对 —— 方案：predict_l15 接收
             (my_panel, opp_panel, my_power, opp_power)，任一 panel None
             时用 my_power/opp_power 走 L0。
  双 panel 齐：
    d_dps = my.dps - opp.dps; d_ehp 同; d_burst 同
    diff = 0.45*d_dps + 0.35*d_ehp + 0.20*d_burst      # 三轴权重
    diff += pos_penalty(pos_ctx)                        # 站位修正 -5..+3
    winrate = sigmoid(K15 * diff)，K15=0.09 初始标定
    tier/confidence 沿用 matchup.py 三档阈值（0.65/0.35）与置信度规则
```

- **复用 L0 的常量**（TIER_HIGH/TIER_LOW）：从 matchup.py import，不复制魔法数。
- advice_for 复用：L15Prediction 是 MatchupPrediction 的超集（多 engine/detail 字段），advice_for(pred) 直接兼容。

### 3.5 站位粗算（decision/positioning.py）

```
PositionContext = dataclass(my_front_ratio, opp_melee_count, my_backline_exposed)

classify(state, book) -> PositionContext
  melees = units with range==1；ranged = range>=4（range 2-3 归近战侧）
  front_ratio = 前两排格位(0-7) 中有子的占比 → 见格位定义
pos_penalty(ctx) -> float   # -5.0 .. +3.0
  我方后排远程多 且 对方近战多 且 front_ratio<0.3（沉底）→ -5（被冲脸）
  我方 front_ratio>=0.6（顶前）且对方近战少 → +2（压制）
  其余 0；缺 positions 数据 → 0（降级不炸）
```

- 格位定义：0-27 线性编号，0-7 前两排（左上起横向），8-15 中排，16-27 后排。PlayerState.positions 为可选 dict，未提供时 front_ratio 按 range 分布推断（近战默认前排）。

### 3.7 power_score item 分量接入（AC5.5）

```
PowerScorer.__init__ 加可选 equips_book=None
score() 中 item = Σ items grade 权重（UnitOnBoard.items 的 id 查表），
  归一基准：10 件成装（10×1.0）=100 分锚点；equips_book=None 或
  items 空 → item=0（降级不炸，M3 行为兼容）
```

- snapshot.UnitOnBoard 加 `items: tuple[str, ...] = ()`（默认空，frozen dataclass 兼容既有构造）。
- 既有测试不受影响（默认空 items → item=0 与 M3 恒 0 等价）。

## 6. 风险点与对策

| 风险 | 对策 |
|---|---|
| M3 既有测试因 item 分量激活而分值漂移 | items 默认空 tuple → item=0，M3 全部既有用例分值不变（回归验证） |
| sigmoid K15=0.09 标定无真机数据 | 合成局验证方向性（强阵容胜率>弱阵容），K15 与 L0 K=0.08 同量级；M6 回归重估 |
| 站位 positions 感知层 M2 未产出 | positions 可选，缺省走 range 推断，永远有值不炸 |
| equips desc 为空字符串（基础装备多为空） | desc 可空，校验只要求 name/id/type/grade |
| 降级链两套输出结构不一致 | L15Prediction 兼容 MatchupPrediction 字段（winrate/tier/confidence 同名同义），advice_for 复用 |
