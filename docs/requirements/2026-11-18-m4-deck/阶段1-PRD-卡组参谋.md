# 阶段1-PRD-卡组参谋（M4）

> 状态基线：M3 已合入 main（a194733）。数据源调研完成（见附录）。用户授权按 M2/M3 先例连续执行。

## 1. 背景与目标

大橘大利模式开局选 3 张时间卡片（201 张卡池，星级 1-5）。选卡无任何提示，新手全靠感觉。
M4 交付局前卡组参谋：输入偏好 → 输出 Top5 卡组 + 阶段策略说明。

## 3. 用户故事

- US1：作为玩家，我开局面对 201 张时间卡片不知所措，希望工具告诉我带哪 3 张。
- US2：作为玩家，我希望按我的偏好（连败流/平滑运营/传送门流）得到不同推荐。
- US3：作为玩家，我关心每张卡为什么被推荐，希望看到理由（阶段策略说明）。
- US4：作为玩家，我希望推荐结果不差于「明星卡组」基线（合理性底线）。

## 4. 功能需求

### F1 时间卡片库 + loader
- data/cards/cards_18.6.json：201 张卡，每卡字段 id/name/star/icon_url/effect_desc(可空)/effect_tags/energy_cost(可空)
- effect_desc 生成路线：LLM 知识初稿 + quality_flags.desc_missing 标记 + 人工校验清单输出
- loader 三重校验（对齐 units_loader 铁律）：文件名版本==meta.patch==卡池规模

### F2 羁绊断点表合并
- data/traits/traits_18.6.json：58 羁绊，断点 num_list + effect_desc + members（含费用）
- traits_loader.py + 三重校验；M3 战力评分的羁绊分升级为真实断点权重

## 5. 非功能需求

- 性能：组合推演 200³/6 ≈ 131万组合 → 剪枝到 200-300 组，全流程 ≤5s
- 红线不变：零网络零输入模拟零进程读取；LLM 生成仅在 tools/ 开发期
- 测试：pytest 全绿 + ruff + semgrep（正向验证过）
