# 阶段2-技术方案-M2 感知层

> 基于 PRD（验收标准 A1-A6 共 8 条）覆盖情况：A1/A2/A3/A4/A4b/A5/A5b/A6 全覆盖，无偏离。
> 前置决策：合成帧验证口径（Q1）、无 PaddleOCR（Q2）、程序合成模板（Q3/Q4）。

## 1. 模块设计

| 模块 | 文件 | 聝责 | 预算 |
|---|---|---|---|
| ScreenGrabber | perception/grabber.py | mss 截屏→BGR ndarray；黑屏率统计；L1 PIL 兜底 | 30ms/frame |
| TemplateBank | perception/templates.py | 122 头像 + 合成数字/角标模板管理，版本目录加载 | 10ms/frame |
| SceneScheduler | perception/scene.py | 全屏锚点→8 场景枚举；场景降频策略表 | 15ms/frame |
| NumberReader | perception/numbers.py | ROI→数字串（cv2 悲观分割+模板匹配） | 60ms/frame |
| UnitSpotter | perception/units_spotter.py | ROI→UnitBox 列表（多尺度模板匹配+边框色环） | 100ms/frame |
| 合成帧引擎 | tests/unit/perception_synth.py | 合成帧生成（真实头像+噪声+亮度扰动） | 测试专用 |
| anchors 配置 | data/templates/v18.6/anchors.json | ROI 坐标版本化 | - |

**关键决策 4 条**：
- **D1 第一公民原则**：感知层输入/输出以 ndarray(BGR) 为第一公民，mss 只是取帧器——识别算法不依赖 mss，合成帧可直接喂入（CI 无显示器也能跑全量测试）。
- **D2 官方头像做模板**：棋盘小头像与官方头像同源（game.gtimg.cn 图床），采用官方头像 + 多尺度匹配（0.6/0.8/1.0/1.2/1.4）兜住缩放差异，真机校准移交 M6。
- **D3 星角标程序合成**：罗马数字 I/II/III（银/金）cv2 程序绘制模板，阈值放宽，M6 替换真机模板。
- **D4 数字悲观分割**：ROI 内连通域分割（宽高比/间距约束）→ 逐字符模板匹配，比投影法更稳。五色池（白/黄/金/红/蓝）按 ROI 亮度自适应。

## 2. 数据流（单帧）

```
mss frame(BGRA) -> grabber.BGR ndarray
  |- scene.SceneScheduler.detect(frame) -> GameScene 枚举        [15ms]
  |- numbers.NumberReader.read(frame, roi_key) -> int|None     [60ms/ROI]
  `- units_spotter.UnitSpotter.spot(frame, area) -> list[UnitBox] [100ms]
```

UnitBox: {unit_id, name, cost, star, bbox, score}；star 由角标匹配并入。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 合成帧与真机帧差距 | 真机校准 M6；模板尺寸/阈值全参数化 |
| mss 部分环境不可用 | L1 PIL ImageGrab 兜底 + 黑屏率监测自动切换 |
| 多尺度匹配性能 | 灰度化 + 缩放金字塔 LUT，预算内 |
| 星角标合成与真机差异 | 阈值放宽 + M6 真机模板替换 |
| 版本串档 | 三重校验 + anchors.json 版本目录隔离 |

## 6. 实现顺序

1. anchors.json + tests 合成帧引擎（测试基础设施）
2. grabber.py -> templates.py -> numbers.py -> scene.py -> units_spotter.py
3. perception-test CLI + 集成测试（40 帧）+ perf 采样
