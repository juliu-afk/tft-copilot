## 1. 背景与问题

tft-copilot 的决策四模块（层数进度/战力评分/对位预测/影响推演）全部依赖静态知识库。目前知识只存在于人工整理的攻略 HTML 里，程序无法消费。本迭代把「大橘大利 18.6」核心攻略数据结构化为带版本号的 JSON，作为整个工具的地基。

## 2. 目标 / 非目标

**目标**：
- 将 38 项以绪塔尔任务的逐阶段变体（数量要求 + 层数奖励 + 评级 + 路线关联）结构化
- 将 20 档层数奖励表（1~1250 层）结构化
- 将 2 把钥匙（秩序/科技）解锁条件与效果结构化
- 将 4 条路线（连败/连胜/平稳/血量换层）的任务推荐序列结构化
- 提供带三重校验的加载器（版本对齐铁律，v1.1 P0-2 落地）

**非目标**：
- 弈子面板数值库（M2 掌盟爬取）
- 时间卡片库（M4 卡组参谋）
- 感知层任何内容（M2 起）
- 路线推荐的自动推理——本迭代只存人工结论，不做计算

## 3. 用户故事

- 作为「影响推演模块」开发者，我要 `query_task(stage=4, route="lose_streak")` 拿到该阶段该路线推荐任务及其层数，用于生成 Toast 提醒
- 作为「层数进度模块」开发者，我要 `next_reward(current_layers=412)` 拿到下一个奖励档位（450 层）及奖励选项，用于里程碑预警
- 作为维护者，版本更新后我要能新建 `rules_18.7.json` 并让加载器在数据与当前游戏版本不匹配时拒绝加载或警告

## 4. 功能需求

| # | 需求 | 优先级 |
|---|---|---|

## 5. 验收标准（AC）

- [ ] AC1：`python -m tft_copilot.rules_check` 打印 38 任务 / 20 奖励档 / 2 钥匙 / 4 路线统计，无校验错误
- [ ] AC2：`tasks_by_stage_route(4, "lose_streak")` 返回「单位阵亡/击杀/利息」相关任务且层数正确（175/110/120 档）

- [ ] AC5：meta.patch 与文件名版本不一致时加载器抛 VersionMismatchError
- [ ] AC6：pytest 单元测试 ≥12 个用例全绿
- [ ] AC7：semgrep 三红线扫描零命中（本迭代不涉输入模拟/进程读取/联网，预期天然通过）
